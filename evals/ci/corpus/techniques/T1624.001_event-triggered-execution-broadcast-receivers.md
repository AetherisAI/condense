# T1624.001 — Event Triggered Execution: Broadcast Receivers

- **Type:** sub-technique of T1624 Event Triggered Execution
- **Domain:** Mobile ATT&CK
- **Tactics:** Persistence
- **Platforms:** Android
- **ATT&CK URL:** https://attack.mitre.org/techniques/T1624/001
- **Last modified:** 2026-05-12

## Description

Adversaries may establish persistence using system mechanisms that trigger execution based on specific events. Mobile operating systems have means to subscribe to events such as receiving an SMS message, device boot completion, or other device activities. 

An intent is a message passed between Android applications or system components. Applications can register to receive broadcast intents at runtime, which are system-wide intents delivered to each app when certain events happen on the device, such as network changes or the user unlocking the screen. Malicious applications can then trigger certain actions within the app based on which broadcast intent was received. 

In addition to Android system intents, malicious applications can register for intents broadcasted by other applications. This allows the malware to respond based on actions in other applications. This behavior typically indicates a more intimate knowledge, or potentially the targeting of specific devices, users, or applications. 

In Android 8 (API level 26), broadcast intent behavior was changed, limiting the implicit intents that applications can register for in the manifest. In most cases, applications that register through the manifest will no longer receive the broadcasts. Now, applications must register context-specific broadcast receivers while the user is actively using the app.

## Mitigations

- **M1006 Use Recent OS Version** — Android 8 introduced additional limitations on the implicit intents that an application can register for.

## Detection strategies

- **DET0711 Detection of Broadcast Receivers**
  - AN1837 (Android): For Android, detect Broadcast Receivers primarily during application vetting or controlled analysis rather than assuming a live device SOC feed. Correlate OS API Execution via Application Vetting / Instrumented Dynamic Analysis [Dynamic API/runtime trace: Application registers BroadcastReceiver via registerReceiver() or manifest-declared receiver for sensitive system intents (BOOT_COMPLETED, SMS_RECEIVED, ACTION_PACKAGE_REPLACED, CONNECTIVITY_CHANGE, USER_PRESENT) NOT IN $ApprovedReceiverApp]. Alert on a sequence or state change inconsistent with the device/app baseline, approved management policy, or expected user workflow; do not infer unobserved API calls, file/process activity, or payload content from management state alone. Log sources: mobile:DynamicAnalysis (Dynamic API/runtime trace: Application registers BroadcastReceiver via registerReceiver() or manifest-declared receiver for sensitive system intents (BOOT_COMPLETED, SMS_RECEIVED, ACTION_PACKAGE_REPLACED, CONNECTIVITY_CHANGE, USER_PRESENT) NOT IN $ApprovedReceiverApp).

## Procedure examples

- **C0033 C0033** (campaign) — During C0033, PROMETHIUM used StrongPity to receive the following broadcast events to establish persistence: `BOOT_COMPLETED`, `BATTERY_LOW`,`USER_PRESENT`, `SCREEN_ON`, `SCREEN_OFF`, or `CONNECTIVITY_CHANGE`.
- **S0305 SpyNote RAT** (software) — SpyNote RAT uses an Android broadcast receiver to automatically start when the device boots.
- **S0316 Pegasus for Android** (software) — Pegasus for Android listens for the `BOOT_COMPLETED` broadcast intent in order to maintain persistence and activate its functionality at device boot time.
- **S0324 SpyDealer** (software) — SpyDealer registers the broadcast receiver to listen for events related to device boot-up.
- **S0408 FlexiSpy** (software) — FlexiSpy uses root access to establish reboot hooks to re-install the application from `/data/misc/adn`. At boot, FlexiSpy spawns daemons for process monitoring, call monitoring, call managing, and system.
- **S0419 SimBad** (software) — SimBad registers for the `BOOT_COMPLETED` and `USER_PRESENT` broadcast intents, which allows the software to perform actions after the device is booted and when the user is using the device, respectively.
- **S0421 GolfSpy** (software) — GolfSpy registers for the `USER_PRESENT` broadcast intent and uses it as a trigger to take photos with the front-facing camera.
- **S0427 TrickMo** (software) — TrickMo registers for the `SCREEN_ON` and `SMS_DELIVER` intents to perform actions when the device is unlocked and when the device receives an SMS message.
- **S0478 EventBot** (software) — EventBot registers for the `BOOT_COMPLETED` intent to auto-start after the device boots.
- **S0479 DEFENSOR ID** (software) — DEFENSOR ID abuses the accessibility service to auto-start the malware on device boot. This is accomplished by receiving the `android.accessibilityservice.AccessibilityService` intent.
- **S0509 FakeSpy** (software) — FakeSpy can register for the `BOOT_COMPLETED` broadcast Intent.
- **S0522 Exobot** (software) — Exobot has registered to receive the `BOOT_COMPLETED` broadcast intent.
- **S0524 AndroidOS/MalLocker.B** (software) — AndroidOS/MalLocker.B has registered to receive 14 different broadcast intents for automatically triggering malware payloads.
- **S0525 Android/AdDisplay.Ashas** (software) — Android/AdDisplay.Ashas has registered to receive the `BOOT_COMPLETED` broadcast intent to activate on device startup.
- **S0536 GPlayed** (software) — GPlayed can register for the `BOOT_COMPLETED` broadcast intent.
- **S0544 HenBox** (software) — HenBox has registered several broadcast receivers.
- **S0545 TERRACOTTA** (software) — TERRACOTTA has registered several broadcast receivers.
- **S0558 Tiktok Pro** (software) — Tiktok Pro has registered for device boot, incoming, and outgoing calls broadcast intents.
- **S1095 AhRat** (software) — AhRat can register with the `CONNECTIVITY_CHANGE` and `WIFI_STATE_CHANGED` broadcast events to trigger further functionality.
- **S1103 FlixOnline** (software) — FlixOnline may use the `BOOT_COMPLETED` action to trigger further scripts on boot.
- **S1195 SpyC23** (software) — SpyC23 listens for the `BOOT_COMPLETED` broadcast to activate malware.
- **S9005 DocSwap** (software) — DocSwap has registered the following intents to automatically execute MainService on device reboot: `android.intent.action.BOOT_COMPLETED`, `android.intent.action.ACTION_POWER_CONNECTED`, and `android.intent.action.ACTION_POWER_DISCONNECTED`.
