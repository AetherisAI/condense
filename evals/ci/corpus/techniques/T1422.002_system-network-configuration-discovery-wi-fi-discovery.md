# T1422.002 — System Network Configuration Discovery: Wi-Fi Discovery

- **Type:** sub-technique of T1422 System Network Configuration Discovery
- **Domain:** Mobile ATT&CK
- **Tactics:** Discovery
- **Platforms:** Android, iOS
- **ATT&CK URL:** https://attack.mitre.org/techniques/T1422/002
- **Last modified:** 2026-05-12

## Description

Adversaries may search for information about Wi-Fi networks, such as network names and passwords, on compromised systems. Adversaries may use Wi-Fi information as part of Discovery or Credential Access activity to support both ongoing and future campaigns.

## Mitigations

- **M1006 Use Recent OS Version** — Android 10 introduced changes that prevent normal applications from accessing sensitive device identifiers.

## Detection strategies

- **DET0709 Detection of Wi-Fi Discovery**
  - AN1833 (Android): For Android, detect Wi-Fi Discovery by correlating analyst-visible device/network evidence and management state; use streaming or batched telemetry only where the documented collector is deployed. Correlate API Calls via Application Vetting / Instrumented Dynamic Analysis [Dynamic API/runtime trace: WifiManager.getScanResults()]; Network Traffic Content via Enterprise Secure Web Gateway / Proxy [DNS/HTTP(S) inspection or proxy transaction metadata where enterprise decryption/inspection is deployed]; Permissions Request via Android Enterprise DPC / Application Vetting [DevicePolicyManager.getPermissionGrantState(); PackageManager manifest/requested-permission review]. Alert on a sequence or state change inconsistent with the device/app baseline, approved management policy, or expected user workflow; do not infer unobserved API calls, file/process activity, or payload content from management state alone. Log sources: mobile:DynamicAnalysis (Dynamic API/runtime trace: WifiManager.getScanResults()); webproxy:applog (DNS/HTTP(S) inspection or proxy transaction metadata where enterprise decryption/inspection is deployed); android:DevicePolicyManager (DevicePolicyManager.getPermissionGrantState(); PackageManager manifest/requested-permission review).
  - AN1834 (iOS): For iOS, detect Wi-Fi Discovery by correlating analyst-visible device/network evidence and management state; use streaming or batched telemetry only where the documented collector is deployed. Correlate API Calls via Application Vetting / Instrumented Dynamic Analysis [Dynamic API/runtime trace: CNCopyCurrentNetworkInfo() or NEHotspotHelper.register() called by app NOT IN $WiFiAllowList$]; Network Traffic Content via Enterprise Secure Web Gateway / Proxy [DNS/HTTP(S) inspection or proxy transaction metadata where enterprise decryption/inspection is deployed]; Permissions Request via Application Vetting [Code-signing entitlements and Info.plist privacy usage-description keys]. Alert on a sequence or state change inconsistent with the device/app baseline, approved management policy, or expected user workflow; do not infer unobserved API calls, file/process activity, or payload content from management state alone. Log sources: mobile:DynamicAnalysis (Dynamic API/runtime trace: CNCopyCurrentNetworkInfo() or NEHotspotHelper.register() called by app NOT IN $WiFiAllowList$); webproxy:applog (DNS/HTTP(S) inspection or proxy transaction metadata where enterprise decryption/inspection is deployed); mobile:ApplicationVetting (Code-signing entitlements and Info.plist privacy usage-description keys).

## Procedure examples

- **S0316 Pegasus for Android** (software) — Pegasus for Android checks if the device is on Wi-Fi, a cellular network, and is roaming.
- **S0326 RedDrop** (software) — RedDrop collects and exfiltrates information including IMEI, IMSI, MNC, MCC, nearby Wi-Fi networks, and other device and SIM-related info.
- **S0407 Monokle** (software) — Monokle checks if the device is connected via Wi-Fi or mobile data.
- **S0425 Corona Updates** (software) — Corona Updates can collect device network configuration information, such as Wi-Fi SSID and IMSI.
- **S0427 TrickMo** (software) — TrickMo can collect device network configuration information such as IMSI, IMEI, and Wi-Fi connection state.
- **S0463 INSOMNIA** (software) — INSOMNIA can collect the device’s phone number, ICCID, IMEI, and the currently active network interface (Wi-Fi or cellular).
- **S1056 TianySpy** (software) — TianySpy can check to see if Wi-Fi is enabled.
- **S1077 Hornbill** (software) — Hornbill can collect a device's phone number and IMEI, and can check to see if Wi-Fi is enabled.
- **S1079 BOULDSPY** (software) — BOULDSPY can collect network information, such as IP address, SIM card information, and Wi-Fi information.
- **S1185 LightSpy** (software) — LightSpy uses the WifiList (or `libWifiList`) plugin to gather Wi-Fi network information, such as the SSID, BSSID, signal strength (RSSI), channel, security type, and previously saved networks.
- **S9005 DocSwap** (software) — DocSwap has checked for the `ACCESS_WIFI_STATE` and `CHANGE_WIFI_STATE` permissions.
- **S9006 VajraSpy** (software) — VajraSpy has scanned for Wi-Fi networks.
- **S9048 KoSpy** (software) — KoSpy has collected Wi-Fi network details using dynamically loaded plugins.
