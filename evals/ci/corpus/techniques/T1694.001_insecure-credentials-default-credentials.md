# T1694.001 — Insecure Credentials: Default Credentials

- **Type:** sub-technique of T1694 Insecure Credentials
- **Domain:** ICS ATT&CK
- **Tactics:** Lateral Movement, Persistence
- **Platforms:** Embedded, Windows, Linux, Network Devices
- **ATT&CK URL:** https://attack.mitre.org/techniques/T1694/001
- **Last modified:** 2026-10-13

## Description

Adversaries may leverage manufacturer or supplier set default credentials on control system devices. These default credentials may have administrative permissions and may be necessary for initial configuration of the device. It is general best practice to change the passwords for these accounts as soon as possible, but some manufacturers may have devices that have passwords or usernames that cannot be changed.

Default credentials are normally documented in an instruction manual that is either packaged with the device, published online through official means, or published online through unofficial means. Adversaries may leverage default credentials that have not been properly modified or disabled.

## Mitigations

- **M0801 Access Management** — Ensure embedded controls and network devices are protected through access management, as these devices often have unknown default accounts which could be used to gain unauthorized access.
- **M0927 Password Policies** — Review vendor documents and security alerts for potentially unknown or overlooked default credentials within existing devices.

## Detection strategies

- **DET0756 Detection of Default Credentials**
  - AN1888 (Windows): Real-time monitoring identifies successful authentication to an Industrial Control System (ICS) application such as a Human-Machine Interface (HMI), historian, Supervisory Control and Data Acquisition (SCADA) server using credentials matching known default vendor passwords, from a logon source not associated with any authorized user. OT operational-fidelity gate: Alert only when the account/device/session violates the approved identity + source host/jump path/zone policy and is corroborated by access to a protected OT asset, execution, configuration change, or another security-relevant follow-on event. Suppress approved shift activity, vendor support, break-glass use, commissioning, and documented remote-access windows. Log sources: WinEventLog:Security (Windows Security Event ID 4624/4625: EventCode=4624 for account matching default vendor credential list from source not in approved host list).
  - AN2193 (Network Devices): Real-time monitoring identifies authentication attempts against Industrial Control System (ICS) network device management interfaces using well-known default vendor credentials from source Internet Protocol (IP) addresses not in the approved Network Management System (NMS) Classless Inter-Domain Routing (CIDR) subnet range. OT operational-fidelity gate: Alert only when the account/device/session violates the approved identity + source host/jump path/zone policy and is corroborated by access to a protected OT asset, execution, configuration change, or another security-relevant follow-on event. Suppress approved shift activity, vendor support, break-glass use, commissioning, and documented remote-access windows. Log sources: networkdevice:syslog (Device authentication/audit log: successful authentication using a vendor-default or prohibited account from a non-approved management source).
  - AN2218 (Embedded): Real-time monitoring identifies successful authentication to a field device using credentials matching documented vendor-default values, from a source not in the approved access list. OT operational-fidelity gate: Alert only when the account/device/session violates the approved identity + source host/jump path/zone policy and is corroborated by access to a protected OT asset, execution, configuration change, or another security-relevant follow-on event. Suppress approved shift activity, vendor support, break-glass use, commissioning, and documented remote-access windows. Log sources: NSM:Content (authentication success using credential matching default vendor credential list from source not in engineering workstation list).
  - AN2255 (Linux): Real-time monitoring identifies successful Secure Shell (SSH) or application authentication using credentials matching known default vendor passwords on Industrial Control System (ICS) Linux assets. OT operational-fidelity gate: Alert only when the account/device/session violates the approved identity + source host/jump path/zone policy and is corroborated by access to a protected OT asset, execution, configuration change, or another security-relevant follow-on event. Suppress approved shift activity, vendor support, break-glass use, commissioning, and documented remote-access windows. Log sources: syslog:auth (sshd Accepted for username matching default vendor credential list from source not in approved admin Classless Inter-Domain Routing (CIDR) subnet).

## Procedure examples

- **C0031 Unitronics Defacement Campaign** (campaign) — During the Unitronics Defacement Campaign, the CyberAv3ngers discovered and exploited default credentials found on many Unitronics Programmable Logic Controller (PLC) Human-Machine Interface (HMI). For many of these devices, the default password was set to ‘1111’.
- **C0063 2025 Poland Wiper Attacks** (campaign) — During the 2025 Poland Wiper Attacks, the adversaries used default credentials to access Hitatchi RTUs, Mikronika RTUs, Hitachi Relion Protection and Control Relays, Mikronika HMI Computers, and Moxa NPort Serial Device Servers.
- **C0066 2026 U.S. Water Utilities Attacks** (campaign) — During the 2026 U.S. Water Utilities Attacks, the adversary logged in to internet-exposed PLCs using default credentials.
- **G1027 CyberAv3ngers** (group) — During the 2026 Iranian Water Campaign, CyberAv3ngers accessed internet-accessible equipment using default credentials.
