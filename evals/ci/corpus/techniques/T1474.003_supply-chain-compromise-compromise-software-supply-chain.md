# T1474.003 — Supply Chain Compromise: Compromise Software Supply Chain

- **Type:** sub-technique of T1474 Supply Chain Compromise
- **Domain:** Mobile ATT&CK
- **Tactics:** Initial Access
- **Platforms:** Android, iOS
- **ATT&CK URL:** https://attack.mitre.org/techniques/T1474/003
- **Last modified:** 2025-10-24

## Description

Adversaries may manipulate application software prior to receipt by a final consumer for the purpose of data or system compromise. Supply chain compromise of software can take place in a number of ways, including manipulation of the application source code, manipulation of the update/distribution mechanism for that software, or replacing compiled releases with a modified version.

## Mitigations

- **M1001 Security Updates** — Security updates may contain patches that inhibit system software compromises.
- **M1004 System Partition Integrity** — Ensure Verified Boot is enabled on devices with that capability.

## Detection strategies

- **DET0721 Detection of Compromise Software Supply Chain**
  - AN1853 (Android): For Android, detect Compromise Software Supply Chain from documented management, network, or vetting evidence; treat state queries as periodic observations rather than real-time events. Correlate Application Permission via Android Enterprise DPC / Application Vetting [DevicePolicyManager.getPermissionGrantState(); PackageManager manifest/requested-permission review]; Application State via Android Enterprise / EMM [Managed package inventory/status and package metadata]; File Creation via Application Vetting / Forensic Acquisition [Dynamic filesystem trace or acquired app-container/filesystem artifacts: Compromised app writes staging, cache, or export artifacts inconsistent with its declared function within $PostInstallWindow$]. Alert on a sequence or state change inconsistent with the device/app baseline, approved management policy, or expected user workflow; do not infer unobserved API calls, file/process activity, or payload content from management state alone. Log sources: android:DevicePolicyManager (DevicePolicyManager.getPermissionGrantState(); PackageManager manifest/requested-permission review); android:EMM (Managed package inventory/status and package metadata); mobile:ForensicArtifacts (Dynamic filesystem trace or acquired app-container/filesystem artifacts: Compromised app writes staging, cache, or export artifacts inconsistent with its declared function within $PostInstallWindow$); mobile:DynamicAnalysis (Dynamic API/runtime trace: Recently updated trusted app invokes special-access paths, account services, or accessibility not present in prior version baseline).
  - AN1854 (iOS): For iOS, detect Compromise Software Supply Chain from documented management, network, or vetting evidence; treat state queries as periodic observations rather than real-time events. Correlate Application Permission via Application Vetting [Code-signing entitlements and Info.plist privacy usage-description keys]; Application State via Apple MDM [InstalledApplicationList / ManagedApplicationList]; OS API Execution via Application Vetting / Instrumented Dynamic Analysis [Dynamic API/runtime trace: Launch services, extension-handling, or framework subsystem anomalies occur near install or first launch of recently updated trusted app on supervised device]. Alert on a sequence or state change inconsistent with the device/app baseline, approved management policy, or expected user workflow; do not infer unobserved API calls, file/process activity, or payload content from management state alone. Log sources: mobile:ApplicationVetting (Code-signing entitlements and Info.plist privacy usage-description keys); iOS:MDM (InstalledApplicationList / ManagedApplicationList); mobile:DynamicAnalysis (Dynamic API/runtime trace: Launch services, extension-handling, or framework subsystem anomalies occur near install or first launch of recently updated trusted app on supervised device).

## Procedure examples

- **S0309 Adups** (software) — Adups was pre-installed on Android devices from some vendors.
- **S0319 Allwinner** (software) — A Linux kernel distributed by Allwinner reportedly contained an simple backdoor that could be used to obtain root access. It was believed to have been left in the kernel by mistake by the authors.
- **S0328 Stealth Mango** (software) — In at least one case, Stealth Mango may have been installed using physical access to the device by a repair shop.
- **S0424 Triada** (software) — Triada was added into the Android system by a third-party vendor identified as Yehuo or Blazefire during the production process.
- **S0555 CHEMISTGAMES** (software) — CHEMISTGAMES has been distributed as updates to legitimate applications. This was accomplished by compromising legitimate app developers, and subsequently gaining access to their Google Play Store developer account.
