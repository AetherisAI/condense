# T1417.002 — Input Capture: GUI Input Capture

- **Type:** sub-technique of T1417 Input Capture
- **Domain:** Mobile ATT&CK
- **Tactics:** Collection, Credential Access
- **Platforms:** Android, iOS
- **ATT&CK URL:** https://attack.mitre.org/techniques/T1417/002
- **Last modified:** 2026-05-12

## Description

Adversaries may mimic common operating system GUI components to prompt users for sensitive information with a seemingly legitimate prompt. The operating system and installed applications often have legitimate needs to prompt the user for sensitive information such as account credentials, bank account information, or Personally Identifiable Information (PII). Compared to traditional PCs, the constrained display size of mobile devices may impair the ability to provide users with contextual information, making users more susceptible to this technique’s use.

There are several approaches adversaries may use to mimic this functionality. Adversaries may impersonate the identity of a legitimate application (e.g. use the same application name and/or icon) and, when installed on the device, may prompt the user for sensitive information. Adversaries may also send fake device notifications to the user that may trigger the display of an input prompt when clicked. 

Additionally, adversaries may display a prompt on top of a running, legitimate application to trick users into entering sensitive information into a malicious application rather than the legitimate application. Typically, adversaries need to know when the targeted application and the individual activity within the targeted application is running in the foreground to display the prompt at the proper time. Adversaries can abuse Android’s accessibility features to determine which application is currently in the foreground. Two known approaches to displaying a prompt include:

* Adversaries start a new activity on top of a running legitimate application. Android 10 places new restrictions on the ability for an application to start a new activity on top of another application, which may make it more difficult for adversaries to utilize this technique.
* Adversaries create an application overlay window on top of a running legitimate application. Applications must hold the `SYSTEM_ALERT_WINDOW` permission to create overlay windows. This permission is handled differently than typical Android permissions and, at least under certain conditions, is automatically granted to applications installed from the Google Play Store. The `SYSTEM_ALERT_WINDOW` permission and its associated ability to create application overlay windows are expected to be deprecated in a future release of Android in favor of a new API.

## Mitigations

- **M1006 Use Recent OS Version** — The `HIDE_OVERLAY_WINDOWS` permission was introduced in Android 12 allowing apps to hide overlay windows of type `TYPE_APPLICATION_OVERLAY` drawn by other apps with the `SYSTEM_ALERT_WINDOW` permission, preventing other applications from creating overlay windows on top of the current application.
- **M1012 Enterprise Policy** — An EMM/MDM can use the Android `DevicePolicyManager.setPermittedAccessibilityServices` method to set an explicit list of applications that are allowed to use Android's accessibility features.

## Detection strategies

- **DET0676 Detection of GUI Input Capture**
  - AN1778 (Android): For Android, detect GUI Input Capture by correlating analyst-visible device/network evidence and management state; use streaming or batched telemetry only where the documented collector is deployed. Correlate Application State via Android Enterprise / EMM [Managed package inventory/status and package metadata]; Network Traffic Content via Enterprise Secure Web Gateway / Proxy [DNS/HTTP(S) inspection or proxy transaction metadata where enterprise decryption/inspection is deployed]; Permissions Request via Android Enterprise DPC / Application Vetting [DevicePolicyManager.getPermissionGrantState(); PackageManager manifest/requested-permission review]. Alert on a sequence or state change inconsistent with the device/app baseline, approved management policy, or expected user workflow; do not infer unobserved API calls, file/process activity, or payload content from management state alone. Log sources: android:EMM (Managed package inventory/status and package metadata); webproxy:applog (DNS/HTTP(S) inspection or proxy transaction metadata where enterprise decryption/inspection is deployed); android:DevicePolicyManager (DevicePolicyManager.getPermissionGrantState(); PackageManager manifest/requested-permission review).
  - AN1779 (iOS): For iOS, detect GUI Input Capture by correlating analyst-visible device/network evidence and management state; use streaming or batched telemetry only where the documented collector is deployed. Correlate Application Permission via Application Vetting [Code-signing entitlements and Info.plist privacy usage-description keys]; Application State via Apple MDM [InstalledApplicationList / ManagedApplicationList]; Network Traffic Content via Enterprise Secure Web Gateway / Proxy [DNS/HTTP(S) inspection or proxy transaction metadata where enterprise decryption/inspection is deployed]. Alert on a sequence or state change inconsistent with the device/app baseline, approved management policy, or expected user workflow; do not infer unobserved API calls, file/process activity, or payload content from management state alone. Log sources: mobile:ApplicationVetting (Code-signing entitlements and Info.plist privacy usage-description keys); iOS:MDM (InstalledApplicationList / ManagedApplicationList); webproxy:applog (DNS/HTTP(S) inspection or proxy transaction metadata where enterprise decryption/inspection is deployed).

## Procedure examples

- **S0297 XcodeGhost** (software) — XcodeGhost can prompt a fake alert dialog to phish user credentials.
- **S0298 Xbot** (software) — Xbot uses phishing pages mimicking Google Play's payment interface as well as bank login pages.
- **S0301 Dendroid** (software) — Dendroid can open a dialog box to ask the user for passwords.
- **S0399 Pallas** (software) — Pallas uses phishing popups to harvest user credentials.
- **S0403 Riltok** (software) — Riltok can open a fake Google Play screen requesting bank card credentials and mimic the screen of relevant mobile banking apps to request user/bank card details.
- **S0406 Gustuff** (software) — Gustuff uses WebView overlays to prompt the user for their device unlock code, as well as banking and cryptocurrency application credentials. Gustuff can also send push notifications pretending to be from a bank, triggering a phishing overlay.
- **S0411 Rotexy** (software) — Rotexy can use phishing overlays to capture users' credit card information.
- **S0422 Anubis** (software) — Anubis can create overlays to capture user credentials for targeted applications.
- **S0423 Ginp** (software) — Ginp can use a multi-step phishing overlay to capture banking credentials and then credit card numbers after login.
- **S0478 EventBot** (software) — EventBot can display popups over running applications.
- **S0480 Cerberus** (software) — Cerberus can generate fake notifications and launch overlay attacks against attacker-specified applications.
- **S0485 Mandrake** (software) — Mandrake can manipulate visual components to trick the user into granting dangerous permissions, and can use phishing overlays and JavaScript injection to capture credentials.
- **S0522 Exobot** (software) — Exobot can show phishing popups when a targeted application is running.
- **S0536 GPlayed** (software) — GPlayed can show a phishing WebView pretending to be a Google service that collects credit card information.
- **S0539 Red Alert 2.0** (software) — Red Alert 2.0 has used malicious overlays to collect banking credentials.
- **S0545 TERRACOTTA** (software) — TERRACOTTA has displayed a form to collect user data after installation.
- **S0558 Tiktok Pro** (software) — Tiktok Pro can launch a fake Facebook login page.
- **S1054 Drinik** (software) — Drinik can use overlays to steal user banking credentials entered into legitimate sites.
- **S1055 SharkBot** (software) — SharkBot can use a WebView with a fake log in site to capture banking credentials.
- **S1056 TianySpy** (software) — TianySpy can utilize WebViews to display fake authentication pages that capture user credentials.
- **S1062 S.O.V.A.** (software) — S.O.V.A. can use overlays capture banking credentials and credit card information, and can open arbitrary WebViews from the C2.
- **S1067 FluBot** (software) — FluBot can add display overlays onto banking apps to capture credit card information.
- **S1069 TangleBot** (software) — TangleBot can use overlays to cover legitimate applications or screens.
- **S1083 Chameleon** (software) — Chameleon has performed overlay attacks against a device by injecting HTML phishing pages into a webview. Chameleon has launched overlay attacks through the “Injection” activity.
- **S1092 Escobar** (software) — Escobar can collect credentials using phishing overlays.
- **S1093 FlyTrap** (software) — FlyTrap has used infected applications with Facebook login prompts to steal credentials.
- **S1094 BRATA** (software) — BRATA can use tailored overlay pages to steal PINs for banking applications.
- **S1103 FlixOnline** (software) — FlixOnline requests overlay permissions, which can allow it to create fake Login screens for other apps.
- **S9004 Crocodilus** (software) — Crocodilus has used its AccessibilityLogging feature to collect user data, such as private keys of specific cryptocurrency wallets.
- **S9040 NGate** (software) — NGate has displayed a fake website to collect the user’s banking information.
