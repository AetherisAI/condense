# T1692.001 — Unauthorized Message: Command Message

- **Type:** sub-technique of T1692 Unauthorized Message
- **Domain:** ICS ATT&CK
- **Tactics:** Evasion, Impair Process Control
- **Platforms:** Embedded, Windows, Linux
- **ATT&CK URL:** https://attack.mitre.org/techniques/T1692/001
- **Last modified:** 2026-10-13

## Description

Adversaries may send unauthorized command messages to instruct control system assets to perform actions outside of their intended functionality, or without the logical preconditions to trigger their expected function. Command messages are used in ICS networks to give direct instructions to control systems devices. If an adversary can send an unauthorized command message to a control system, then it can instruct the control systems device to perform an action outside the normal bounds of the device's actions. An adversary could potentially instruct a control systems device to perform an action that will cause an Impact.. An adversary could also misuse control system devices to store data collected from the network for later use.

In the Dallas Siren incident, adversaries were able to send command messages to activate tornado alarm systems across the city without an impending tornado or other disaster.

## Mitigations

- **M0802 Communication Authenticity** — Protocols used for control functions should provide authenticity through MAC functions or digital signatures. If not, utilize bump-in-the-wire devices or VPNs to enforce communication authenticity between devices that are not capable of supporting this (e.g., legacy controllers, RTUs).
- **M0807 Network Allowlists** — Use host-based allowlists to prevent devices from accepting connections from unauthorized systems. For example, allowlists can be used to ensure devices can only connect with master stations or known management/engineering workstations.
- **M0813 Software Process and Device Authentication** — Devices should authenticate all messages between master and outstation assets.
- **M0818 Validate Program Inputs** — Devices and programs that receive command messages from remote systems (e.g., control servers) should verify those commands before taking any actions on them.
- **M0930 Network Segmentation** — Segment operational assets and their management devices based on their functional role within the process. Enabling more strict isolation to more critical control and operational information within the control environment.
- **M0937 Filter Network Traffic** — Perform inline allowlisting of automation protocol commands to prevent devices from sending unauthorized command or reporting messages. Allow/denylist techniques need to be designed with sufficient accuracy to prevent the unintended blocking of valid messages.

## Detection strategies

- **DET0794 Detection of Unauthorized Command Message**
  - AN1926 (Windows): Real-time monitoring identifies a Windows process generating Industrial Control System (ICS) command messages to field device tags representing physical outputs, from a process that is not the recognized Supervisory Control and Data Acquisition (SCADA) or Distributed Control System (DCS) control application, targeting safety-critical output tags. OT operational-fidelity gate: Alert only when the action is not attributable to an authorized operator/engineering source for the specific target and function, and it is either outside an approved change/maintenance window or lacks matching change-control context; where telemetry permits, require corroborating device, configuration, or process-state effect. Suppress activity that fully matches approved maintenance, commissioning, failover, recovery, or tested control procedures. Log sources: opc:applog (command call to field device output tag from process not matching recognized Supervisory Control and Data Acquisition (SCADA)/Distributed Control System (DCS) control application).
  - AN2153 (Linux): Real-time monitoring identifies a Linux process making Open Platform Communications (OPC) Unified Architecture (UA) write calls or direct Industrial Control System (ICS) protocol command connections to field device output addresses, from a User Identifier (UID) not associated with the authorized control application. OT operational-fidelity gate: Alert only when the action is not attributable to an authorized operator/engineering source for the specific target and function, and it is either outside an approved change/maintenance window or lacks matching change-control context; where telemetry permits, require corroborating device, configuration, or process-state effect. Suppress activity that fully matches approved maintenance, commissioning, failover, recovery, or tested control procedures. Log sources: NSM:Content (decoded ICS protocol write/setpoint operation to a control/output address from a client identity or source not in the approved control-application baseline).
  - AN2212 (Embedded): Real-time monitoring identifies a control/command message arriving at a field device from a source not in the approved control server list, where the command targets safety-critical output points and does not correspond to any scheduled or operator-acknowledged process action. Documented precedent: Industroyer2 connected directly to specific International Electrotechnical Commission (IEC)-104 RTUs and toggled hardcoded Information Object Addresses (IOAs) to OFF using command type 46, targeting circuit breaker outputs. OT operational-fidelity gate: Alert only when the action is not attributable to an authorized operator/engineering source for the specific target and function, and it is either outside an approved change/maintenance window or lacks matching change-control context; where telemetry permits, require corroborating device, configuration, or process-state effect. Suppress activity that fully matches approved maintenance, commissioning, failover, recovery, or tested control procedures. Log sources: operationaldb:AlarmEvent (process state change recorded without preceding operator_ack or scheduled switching order reference); operationaldb:ProcessHistory (multiple safety-critical outputs toggle within rapid toggle window, pattern consistent with scripted issuance); NSM:Content (write/operate command targeting safety-critical output addresses from source not in approved Supervisory Control and Data Acquisition (SCADA) servers).

## Procedure examples

- **C0020 Maroochy Water Breach** (campaign) — In the Maroochy Water Breach, the adversary used a dedicated analog two-way radio system to send false data and instructions to pumping stations and the central computer.
- **C0028 2015 Ukraine Electric Power Attack** (campaign) — During the 2015 Ukraine Electric Power Attack, Sandworm Team issued unauthorized commands to substation breaks after gaining control of operator workstations and accessing a distribution management system (DMS) application.
- **C0030 Triton Safety Instrumented System Attack** (campaign) — In the Triton Safety Instrumented System Attack, TEMP.Veles leveraged Triton to send unauthorized command messages to the Triconex safety controllers.
- **C0034 2022 Ukraine Electric Power Attack** (campaign) — During the 2022 Ukraine Electric Power Attack, Sandworm Team used the MicroSCADA SCIL-API to specify a set of SCADA instructions, including the sending of unauthorized commands to substation devices.
- **G1027 CyberAv3ngers** (group) — During the 2026 Iranian Water Campaign, CyberAv3ngers used the manufacturers’ commercial PLC programming and maintenance software to send unauthorized command messages to multiple victim controllers. These include Rockwell Automation’s Studio Logix 5000 Designer, Schneider Electric’s EcoStruxure Control Expert, and Siemens’ Totally Integrated Automation (TIA) Portal .
- **S0604 Industroyer** (software) — Using its protocol payloads, Industroyer sends unauthorized commands to RTUs to change the state of equipment.
- **S1045 INCONTROLLER** (software) — INCONTROLLER can send custom Modbus commands to write register values on Schneider PLCs. INCONTROLLER can send write tag values on OPC UA servers.
- **S1072 Industroyer2** (software) — Industroyer2 is capable of sending command messages from the compromised device to target remote stations to open data channels, retrieve the location and values of Information Object Addresses (IOAs), and modify the IO state values through Select Before Operate I/O, Select/Execute, and Invert Default State operations.
