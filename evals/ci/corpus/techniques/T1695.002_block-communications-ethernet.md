# T1695.002 — Block Communications: Ethernet

- **Type:** sub-technique of T1695 Block Communications
- **Domain:** ICS ATT&CK
- **Tactics:** Inhibit Response Function
- **Platforms:** Embedded, Windows, Linux, Network Devices
- **ATT&CK URL:** https://attack.mitre.org/techniques/T1695/002
- **Last modified:** 2026-10-13

## Description

Adversaries may block access to Ethernet communications to prevent instructions or configurations messages from reaching target systems and devices. Ethernet connections allow for communications between IT and OT systems and devices. Blocking Ethernet communications may also block command and reporting messages.

An adversary may block Ethernet communications by disabling network interfaces, Service Stop, or conducting an Adversary-in-the-Middle attack and dropping the network traffic.

## Mitigations

- **M0807 Network Allowlists** — Implement network allowlists to minimize network access to only authorized hosts.
- **M0810 Out-of-Band Communications Channel** — Ensure systems and devices have an alternative method for communicating in the event that Ethernet communication channels become unavailable.
- **M0930 Network Segmentation** — Segment operational networks to isolate critical systems and devices that do not require broad network access.

## Detection strategies

- **DET0911 Detection of Block Ethernet**

Suppress activity that fully matches approved maintenance, commissioning, failover, recovery, or tested control procedures. Log sources: WinEventLog:System (network adapter disabled on Industrial Control Systems (ICS) gateway host by process not in authorized network admins).
  - AN2165 (Linux): Real-time monitoring identifies ip link set down commands on Industrial Control System (ICS) Linux gateway hosts by a User Identifier (UID) not in the authorized net admin UIDs, affecting the device subnet interface.
